# 环境与能力探测

## 原则

- 只记录当前 DSH 会话实际探测到的事实，不沿用上一次会话或其他宿主的假设。
- 先做只读探测，再做需要副作用或联网的动作。
- 不预置平台避坑清单；环境差异通过探测、证据和记忆处理。
- 工具缺失、权限不足或输出不可解析时，标记未覆盖，不模拟结果。

## 必记字段

| 字段 | 说明 |
|---|---|
| DSH 版本 | 从会话、安装元数据或用户陈述中确认；不确定就写未知 |
| 模型标识与模式 | 只记录可观察到的模型名、推理强度或路由信息 |
| 工作目录 | 目标在 WSL/DSH 中的实际绝对路径 |
| 目标可见性 | 是否位于 `/workspace` 或当前只读可见视图 |
| 操作系统与架构 | 当前 shell 实际报告的系统与架构 |
| shell 与版本 | 实际执行命令的 shell |
| 解释器 | Python、Node、Java 等的实际路径和版本 |
| Git | 版本、仓库根、当前分支、工作区状态 |
| 构建工具 | 实际可用的构建、测试、包管理工具及版本 |
| 容器/虚拟化 | 运行时是否可用、实际架构、权限 |
| 网络 | 是否可联网、是否被代理或策略限制 |
| 写权限 | 工作区、临时目录、报告目录、外部记忆目录 |
| DSH 技能根 | 用户根、项目根或自定义根的只读/可写状态 |
| 后台作业 | `job_output`、`job_list`、`job_kill` 是否可用 |
| 子代理 | `subagent` 是否挂载；工具名是否被配置改写 |

## 能力状态

每项能力只使用以下状态：

- `present`：已实际调用或确认可用；
- `partial`：存在但版本、权限或参数受限；
- `absent`：确认不可用；
- `unknown`：无法确认，必须标未覆盖。

状态不是布尔值，不能把 `unknown` 写成 `present`。

## DSH 专项探测

1. 确认目标路径真实存在且可读。
2. 确认 `read`、`glob`、`grep` 可用；记录搜索上限和截断提示。
3. 若需要命令，先测试 `bash` 的 `workdir` 和退出码行为。
4. 若命令可能超时，确认后台作业工具可用；不要把“已启动”当成“已完成”。
5. 确认技能目录是否只读；记忆默认写外部目录。
6. 不读取或输出 DSH 凭据、令牌和密钥文件。

## 失败与降级

- 目标不在可见工作区：停止并说明需要用户把只读副本放入 `/workspace`。
- `read` 输出被截断：继续分段读取或标记未覆盖，不能根据截断内容下结论。
- `grep` 达到上限：使用返回的 spill 定位继续读取，或缩小范围。
- `bash` 超时：记录作业 ID，等待终态后读取输出；无法等待则标未覆盖。
- 写权限不确定：不要写报告或记忆，先确认位置。
- 子代理不可用：顺序完成双轴审查，不模拟并行结果。
